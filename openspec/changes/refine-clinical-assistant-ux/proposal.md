## Why

The 2026-10-10 UX audit found a patient-change decision without modal focus protection, a contextual composer reduced to 24.85 px of writing width, and recovery flows that duplicate errors or lose the clinician's place. These findings are present in the inspected continuity implementation and need bounded corrections with evidence tied to the build actually tested.

## What Changes

- Make the existing unsent-work decision an accessible modal with initial focus on `Mantener paciente`, explicit consequences, and safe dismissal. Preserve the existing original-context policy.
- Reflow the composer according to available pane width and announce a retained draft's origin independently of the current patient.
- QUEUE-001: make existing individual queue removal visibly `Quitar`, with exact-ID names, claim-boundary safety and failed-delivery recovery. Reuse the incumbent queue; omit bulk clearing.
- Separate thread-load failure from a successful empty thread; expose a read-only retry on the same thread and give each failed operation one feedback owner.
- Show the review recovery dock when its destination is outside the visible transcript. Show the full Assistant header's `Pendientes` entry when the sidebar does not already offer a visible usable entry.
- Refresh the already-open pending-work window without collapsing it to page one, preserving reading position and keyboard focus while reconciling authoritative results.
- PENDING-001: reuse the pending list for patient-scoped rejection of approvals and logical discard of recoverable drafts. Plan the approved localized backend exception: hardened decline, a typed artifact-discard command, read-only canonical reconciliation and a minimal artifact receipt/status migration.
- Make artifact headings follow their containing page or section. Show evolution date and time as `DD mes AAAA · HH:mm`, preserving the current abbreviated Spanish month and timezone behavior, and update the conflicting design sentence.
- Extend DE01 with measurable compact-header acceptance for long patient names, retaining complete authorized identity and required controls. Add C7 for distinguishing clinical conversation rows using existing non-content metadata and for preventing the mobile navigation trigger from covering the disconnected-Drive banner in Assistant views.
- Add a build-provenance verification gate and direct regression coverage for every changed behavior. Cover all findings R01–R11, including the navigation observation R10.
- Add C6 after C1–C5 for three source-backed design-engineering gaps: visible-viewport editing with the mobile keyboard, bounded context-modal content and portaled touch targets, and distinguishable attached-source names. Keep the existing motion policy and require reproduction before any corrective application edit.

## Additive queue and pending-work control

QUEUE-001 belongs to C1 task 1.5, owned by ClinicalAssistantArea and existing ClinicalRuntimeProvider memory. Removal already filters by ID, but the control displays `×`; claimed delivery disappears before its asynchronous result. Removal must win only before claim, preserve other work and never cancel an active turn. Failed delivery restores the original entry once and remains paused until canonical same-thread reconciliation. Removing the final queued entry must not leave an unrelated failure lock on new work. No `Vaciar cola`, new queue or protocol is included.

PENDING-001 belongs to C4 tasks 4.5–4.8 after 4.1–4.4. Existing decline remains the approval command; its transaction will validate stored owner/patient/thread/action/artifact, proposal hash, state/version, approved results and absence of an active turn. Approval rejection keeps action/artifact `declined` with existing resolver/time audit. No parallel approval system is introduced.

Recoverable drafts are artifacts in `draft` or `stale`, not pending actions. The selected command is POST /clinical-threads/{thread_id}/artifacts/{artifact_id}/discard in the existing clinical_artifacts route module. It transitions only eligible artifacts to a distinct `discarded` state and atomically records operation UUID, actor, input version and existing resolution timestamp. The minimal migration extends the artifact status constraint and adds three nullable receipt columns with integrity checks and a scoped unique index. It does not modify or backfill approved clinical data. Return-to-editing, recovery, empty edits and thread deletion are explicitly rejected substitutes.

Use GET /clinical-threads/{thread_id}?read_only=true for canonical identity/hash/version and receipt reconciliation. This new explicit mode performs no expiry/stale-turn cleanup or provider work; incumbent GET behavior remains unchanged for other callers. Reuse PatientOverview/PatientDetail to mount the existing ClinicalPendingWork inline with patient/kind scope, rather than add a route or view. Read-backed counters and C4 window continuity remain authoritative.

Execution order is C0, C1–C5 serially (1.5 in C1; C4 RED 4.5 → backend GREEN 4.6 → frontend GREEN 4.7 → VERIFY 4.8), C6, C7, integrated verification. Backend ownership is routes/clinical_artifacts.py and routes/clinical_assistant.py → clinical_assistant/service.py/schemas.py → db/clinical_assistant_repo.py, with a new migration only during separately authorized implementation. The server enforces non-reactivation in competing writers; frontend hiding is not authorization. All previous clinical, QUEUE-001, C3/C4 and external gates remain intact.
