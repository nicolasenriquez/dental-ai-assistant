# Odontogram human workflow

Verify manual conditions, corrections, conflicts, responsive tooth selection and safe patient navigation. The harden-change acceptance source is `openspec/changes/harden-odontogram-human-workflow/specs/odontogram-human-workflow/spec.md`, with `visual-contract.md`. Its [UAT report](../../../../docs/verification/odontogram-uat-20261006.md) remains that change's acceptance record: green component tests do not close its three observed R7/R8/R9 findings, and the mirror evidence below does not re-certify them. Current shipped behavior for the mirrored interactions (direct tool application, treatments, plans, dental notes) is implemented and evidenced by `openspec/changes/mirror-dental-diagnosis-workspace/` (tasks/evidence, release-gate notes); that change is not yet synced or archived.

## Sub-features

- ODO-LIFECYCLE: create/edit/resolve/correct, mandatory reason, optional replacement, immutable original and recurrence identity.
- ODO-READS: Actuales default, historical record/revision, author UUID, Activity, 50/51/500 paging, explicit incomplete reads.
- ODO-CONFLICT: base/local/current and field choices, repeated 409, terminal guards, correction vs resolution D-03.
- ODO-SPATIAL: all 32 permanent/20 primary pieces, six exact CSS sizes, keyboard, hover, compact editor, contextual Assistant.
- ODO-CONTINUITY: canonical tab/clinical/condition URL, reload, back/forward, draft cancel/discard, invalid enums/UUID.
- ODO-MIRROR: direct whole-tooth/occlusal application and lateral Confirmar, no-tool contextual popover, 63-variant treatment catalog with 8 categories, multi/whole-arch procedures with bridge roles, Planificación/Planes lifecycle and staged execution, and editable diagnosis/treatment/plan notes with templates, tooth binding, body-only edit, logical delete and history.

## How to get to it (user POV)

Sign in → Pacientes → synthetic patient ficha → Clínica → Diagnóstico. Enter a saved condition through Editar condición, Resolver condición, Corregir registro or Historial de condición. Procedure cards, Planificación/Planes and the dental-note composer are the mirrored entry points for the new resources. Activity has exact record links. Both direct `?tab=clinical&clinical=diagnosis&condition=<UUID>` entry and a UI-generated record focus must be checked; proving only the direct link misses UAT-03.

## Driving it with Playwright CLI

Preconditions: an owned disposable instance, or explicit user authorization to create and retain a synthetic patient on a named existing account. There is no patient-delete API. Never mutate an existing clinical patient. Preserve pre-existing Docker services and authenticated browser sessions. For the native Codex browser, use its documented Playwright controls; it does not advertise a Playwright CLI/CDP endpoint. Do not extract cookies to bridge tools or assume that `attach --cdp=chrome` attaches the native browser.

- **Doctor:** `curl.exe -s http://localhost:8000/api/health` must show ok/Postgres. Read `/api/auth/config`; observe the authenticated ficha and loaded `script[src]` asset. Health alone does not establish build freshness. If code and rendered controls differ, report that difference before requesting a rebuild of the shared app. The live image in the 2026-10-06 UAT was updated only after authorization.
- **CLI setup:** use an explicitly owned, local-auth instance. On this Windows machine the verified executable is `C:/nvm4w/nodejs/playwright-cli.cmd`. Set `PWTEST_DAEMON_SESSION_DIR` to a directory inside `.playwright-cli/` if its normal AppData directory is unavailable. Use a unique session name. `playwright-cli -s=<run> open <owned-origin>/patients` creates a separate session; it does not reuse Codex native login. Use approved fixture authentication or human login, never secrets as CLI literals/storage artifacts.
- **Lifecycle:** use current snapshot refs or observed roles. Without a tool, tooth activation opens the contextual popover and must not write. With a tool selected, a whole-tooth or occlusal-surface activation applies directly once; a lateral surface selection opens the compact modal and `Confirmar` applies once — no extra Guardar for direct application. Saved-record edits and corrections still open their trapped modal and require `Guardar`. Capture the request result and reload before declaring persistence. Switching dentition or patient with an open editor runs the dirty guard.
- **Correction:** open Corregir registro on an owned active/resolved resource. With blank Motivo de corrección, Revisar corrección must be unavailable. Fill a synthetic reason; optionally check Crear registro de reemplazo, change piece and applicability; click Revisar corrección. Volver al borrador must not write. Guardar corrección is the only correction POST. Verify original error status, exact revision, optional replacement UUID/link and current filter. Without replacement verify no new condition. Never claim a recording error is a clinical resolution.
- **Conflict:** open the same synthetic resource in two tabs. Change surfaces remotely and only note locally, then save both. Require base/local/current and the decisions specified by R8, not just successful retention. Repeat with same note and another remote save before retry. A correction racing with resolution must retain reason/replacement, show latest resolved source and require Revisar nueva corrección before another operation. Terminal edit/resolve must stay blocked.
- **Spatial:** `resize 1440 900`, `1280 800`, `1024 768`, `768 1024`, `430 932`, `390 844`; verify actual `innerWidth/innerHeight` before labeling evidence. The native capability applies to the selected tab and browser zoom can change CSS sizes; native resize attempts without actual-size proof are not substitutes. Use `run-code`/`page.setViewportSize` for exact CLI sizing. Activate every tooth in both dentitions, using Superior derecha/izquierda and Inferior derecha/izquierda when paged. Measure visible controls ≥44×44 and document overflow false. Cancel/discard incomplete drafts before dentition switches. Check note height with short/long text, computed field-sizing and ≥four useful initial lines; checking font size or preview alone misses UAT-01. Open Asistente at the three desktop sizes and measure chart width/targets again.
- **Navigation:** start from a bare ficha, click Clínica, require tab=clinical/clinical=diagnosis. Open Historial de condición from UI; require condition=<UUID>; reload and require that exact historical context, not only the diagnosis tab. Evoluciones must drop condition and leaving Clínica must drop clinical/condition. Cancel dirty navigation must retain URL/note; explicit discard must navigate without a write. Invalid condition UUID must cause zero exact-read requests.
- **Failure proof:** on the disposable instance only, browser routes may lose a response after a real commit or return a read/catalog 503. Label this browser-only fault injection. Capture frozen correction attempts, one committed revision, GET-only retry after a confirmed save, retained facts on catalog failure, and partial facts plus explicit incomplete state after later-page failure. Do not label injected faults as naturally occurring production failures.
- **Evidence:** use `.playwright-cli/verification/<run>/` for sanitized JSON, scoped screenshots, scripts and notes. Never save cookies, authenticated storage or credentials. Owned synthetic names/notes may be captured; avoid account identity or existing patient content. The executed 2026-10-06 CLI recipes are retained in `.playwright-cli/verification/odontogram-uat-20261006/cli-*.js`; `run-code --filename=<file>` is their invocation. They require the owned localhost:8002 target and single-use fixture state, so do not replay them against the shared stack. The report maps every artifact to its boundary.
- **Cleanup:** close only the CLI session created for the run and only owned scratch tabs. Preserve the user's native tab/ficha. Tear down only the exclusively owned Compose project, including its volume after confirming it is disposable. Never delete the shared patient or volume. Evidence must survive cleanup. Report any deliberately retained synthetic patient.

## Gotchas

Actuales is a status view, not a normal-examination inference. Optional empty surfaces must remain Sin superficies especificadas for surface-capable concepts; reserve Pieza completa, sin superficies for whole-tooth concepts. Unknown codes/categorization cannot authorize new writes. A failed catalog must not hide independent saved evidence.

Account labels must use the persisted actor, not current session/email. An exact receipt revision can differ from current state. Count conditions and distinct pieces separately only after complete reads. Failed pages must not produce a false empty chart.

The signup IP guard may block a second synthetic account with 429; do not bypass it. Use the repository's live disposable-DB ownership tests for that boundary and disclose the browser scenario as unexecuted. Real screen readers/device keyboards and clinician review are separate gates. A passed CLI matrix or green test suite does not override a reproducible acceptance failure. Use `/maintain-verification-skill` when flows change.
