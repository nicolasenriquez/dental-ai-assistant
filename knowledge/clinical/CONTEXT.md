# Clinical knowledge

Reviewed dental terminology authoring workspace. This tree is the editable
source of truth for the clinical glossary the application bundles. It
contains no patient information.

## Routing

| Task | Go to |
|---|---|
| Add or change a concept | `concepts/CONTEXT.md` |
| Register or review a source | `sources/CONTEXT.md` |
| Check schema, policy, or release rules | `_meta/CONTEXT.md` |
| Run intake, review, release | `pipeline/CONTEXT.md` |

## Source of truth and generated artifacts

Editable here: `_meta/catalog.toml`, `sources/sources.toml`, and
`concepts/**/*.md`.

Generated by the compiler: `app/backend/data/dental_ai_glossary_es_cl_v1.json`,
`app/backend/data/dental_ai_glossary_es_cl_v1.sha256`, and
`app/backend/data/dental_ai_glossary_es_cl_v1.manifest.json`. Never hand-edit
generated files; edit the card or registry and rebuild.

The application runtime does not read this tree. It validates the generated
glossary and digest at startup, then synchronizes it transactionally.

## Build

From `app/backend/`:

```bash
uv run python scripts/build_clinical_catalog.py --check
uv run python scripts/build_clinical_catalog.py --write
uv run python scripts/build_clinical_catalog.py --release-check
```

`--check` fails on drift and never writes. `--release-check` also checks
artifact parity, then fails while review or reuse rights are unresolved.
Neither command establishes permission; current hold lives in
`../../docs/clinical-grounding.md`.
