# Reference examples

Two real working GitHub Actions workflows, not templates. `claude-review.yml` is the event-driven one: every opened or updated pull request runs the project's own review skill — the same skill a headless script or a hook could call, which is the point. Note the deliberate details: read-only `permissions`, `id-token: write` for the action's auth, and `fetch-depth: 0` because a review that diffs against the base branch sees nothing at depth 1. `daily-report.yml` is the cron one: time is the trigger, there is no checkout at all, and the plain-text prompt gets exactly two MCP tools because a prompt has no tools until you grant them.

They are inert where they sit — Actions only reads `.github/workflows/` — so copy them there to use them. Change two things for your own project. The **auth secret and the step that invokes the agent** are the only vendor-specific parts of either file: `claude_code_oauth_token` and `anthropics/claude-code-action@v1` are Claude Code's, and another agent means a different secret and usually a `run:` step driving its CLI. The second is the prompt or skill invocation itself — `/piv-review-changes` is this repository's review skill, so name yours. Everything else (triggers, permissions, checkout depth, `--max-turns`) is GitHub Actions and carries across unchanged.
